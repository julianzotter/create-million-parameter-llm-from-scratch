LLM from Scratch

Glossary

Begriffsdefinitionen zum Projekt und Workflow
Dateiformate & Tools
.ipynb Dateiendung für Jupyter Notebooks. Speichert Code, Ausgaben und Markdown in einem JSON-Format.
Notebook Interaktives Dokument aus Code-Zellen, die einzeln ausgeführt werden können. Standard-Tool für explorative Datenarbeit und Prototyping.
Jupyter Notebook Open-Source-Webanwendung zum Erstellen und Ausführen von Notebooks. Unterstützt Python, R und weitere Sprachen.
Colab Link URL zu Google Colaboratory — gehostete Jupyter-Umgebung mit kostenlosem GPU-Zugang. Ermöglicht Ausführung im Browser ohne lokale Installation.
Git & Versionierung
Initial Commit Der erste Commit in einem Git-Repository. Legt die initiale Dateistruktur an.
Recreate Pattern Anti-Pattern: Datei löschen und im nächsten Commit neu erstellen, statt sie direkt zu editieren. Bläht die Git-History unnötig auf.
.gitignore Konfigurationsdatei, die festlegt, welche Dateien/Ordner Git ignorieren soll (z. B. Build-Artefakte, Secrets).
__pycache__ Von Python automatisch erzeugter Ordner mit kompiliertem Bytecode (.pyc). Gehört nicht ins Repository.
.ipynb_checkpoints Auto-Save-Ordner von Jupyter. Enthält Sicherungskopien des Notebooks. Sollte per .gitignore ausgeschlossen werden.
.pyc Kompilierter Python-Bytecode. Wird zur Laufzeit erzeugt und ist plattformspezifisch — nie committen.
Virtual Environment Isolierte Python-Umgebung (venv, conda) mit eigenen Paketen. Der Ordner (oft .venv/) gehört in die .gitignore.
License File Datei im Repo-Root (z. B. LICENSE), die festlegt, unter welchen Bedingungen der Code genutzt werden darf (MIT, Apache, GPL etc.).
Open-Source Projekt Software mit öffentlich einsehbarem Quellcode und einer Lizenz, die Nutzung, Änderung und Weitergabe erlaubt.
Single Branch Alle Commits liegen auf einem einzigen Branch (meist main). Einfach, aber ohne Isolation für parallele Arbeitsströme.
Feature Branches Separate Branches für einzelne Features oder Fixes. Werden nach Fertigstellung per Pull Request in den Hauptbranch gemergt.
Tags Benannte Markierungen auf einem Commit — typisch für Releases (v1.0, v2.1). Unveränderlich, im Gegensatz zu Branches.
Churn Häufiges Ändern, Löschen und Neuerstellen derselben Dateien. Zeichen eines unstrukturierten Workflows.
Pipeline & Daten
Workflow Definierte Abfolge von Arbeitsschritten — hier: Daten laden → Tokenisieren → Trainieren → Evaluieren → Generieren.
Wiederverwendbare Pipeline Modularer, konfigurierbarer Ablauf, der auf verschiedene Datensätze und Aufgaben angewendet werden kann, statt nur einmal hardcoded zu funktionieren.
Daten-Pipeline Die Kette von Datenverarbeitung: Quelle laden → bereinigen → tokenisieren → in Batches aufteilen → an das Modell übergeben.
Hardcoded Werte direkt im Code festgeschrieben statt über Konfiguration steuerbar. Erschwert Wiederverwendung und Anpassung.
TinyShakespeare Kleiner Textdatensatz (~1 Mio. Zeichen) aus Shakespeare-Werken. Standard-Benchmark für character-level Sprachmodelle, populär durch Andrej Karpathy.
Train/Val/Test-Split Aufteilung der Daten in drei Mengen: Training (Lernen), Validation (Hyperparameter-Tuning), Test (finale Bewertung). Typisch: 80/10/10.
Tokenisierung
Tokenizer Wandelt Rohtext in numerische Token um, die das Modell verarbeiten kann. Umgekehrt: Token → Text (Decoding).
Char-Level Tokenisierung auf Zeichenebene — jeder Buchstabe ist ein Token. Einfach, aber großes Vokabular relativ zur Informationsdichte.
BPE Byte Pair Encoding. Algorithmus, der häufige Zeichenpaare iterativ zu neuen Token zusammenfasst. Balance zwischen Char-Level und Wort-Level.
SentencePiece Google-Bibliothek für sprachunabhängige Tokenisierung (BPE oder Unigram). Arbeitet direkt auf Rohtext ohne Vorverarbeitung.
Modell-Architektur
Modell-Architektur Die Gesamtstruktur eines neuronalen Netzes: Schichten, Verbindungen, Normalisierungen und Aktivierungsfunktionen.
RMSNorm Root Mean Square Normalization. Vereinfachte Layer-Normalisierung ohne Mittelwert-Subtraktion. 7–64% schneller als LayerNorm bei vergleichbarer Qualität.
RoPE Rotary Position Embedding. Kodiert Tokenpositionen durch Rotation der Embedding-Vektoren. Relative Abstände werden implizit erfasst.
SwiGLU Swish-Gated Linear Unit. Aktivierungsfunktion, die Swish mit einem Gate-Mechanismus kombiniert. Ersetzt ReLU in LLaMA für bessere Expressivität.
LlamaBlock Ein einzelner Transformer-Block im LLaMA-Stil: RMSNorm → Multi-Head Attention (mit RoPE) → RMSNorm → FFN (mit SwiGLU), jeweils mit Residual-Verbindung.
Llama Das finale Modell: Embedding + N gestapelte LlamaBlocks + Output-FFN. Im Projekt: 4 Schichten, 8 Attention-Heads, ~2,3 Mio. Parameter.
Training
Training-Loop Die Schleife, die das Modell trainiert: Batch laden → Forward Pass → Loss berechnen → Backward Pass → Gewichte updaten. Wiederholen über N Epochen.
train() Die zentrale Trainingsfunktion im Projekt. Nimmt Modell, Optimizer und optional Scheduler entgegen und führt den Training-Loop aus.
Generisch Allgemein gehalten, nicht an einen spezifischen Anwendungsfall gebunden. Ziel bei der Generalisierung des Workflows.
Checkpointing Regelmäßiges Speichern des Modellzustands (Gewichte, Optimizer-State) während des Trainings. Ermöglicht Fortsetzung nach Abbruch.
Early Stopping Training automatisch beenden, wenn der Validation Loss nicht mehr sinkt. Verhindert Overfitting und spart Rechenzeit.
Evaluation
evaluate_loss() Funktion im Projekt, die den mittleren Loss über 10 Batches für Train- und Val-Split berechnet — ohne Gradienten (@torch.no_grad).
BLEU Bilingual Evaluation Understudy. Metrik zum Vergleich von generiertem Text mit Referenztext. Misst n-Gram-Überlappung (0–1, höher = besser).
Inferenz & Sampling
Inference Das trainierte Modell anwenden, um neuen Text zu erzeugen. Kein Lernen — nur Forward Pass und Token-Auswahl.
Sampling-Strategien Methoden zur Token-Auswahl bei der Textgenerierung. Steuern die Balance zwischen Kreativität und Kohärenz.
Temperature Skalierungsfaktor für Logits vor Softmax. Niedrig (z. B. 0.2) → deterministisch/sicher. Hoch (z. B. 1.5) → zufällig/kreativ.
Top-k Nur die k wahrscheinlichsten Token werden für das Sampling zugelassen. Rest wird auf 0 gesetzt. Typisch: k=40–100.
Top-p Nucleus Sampling. Token kumulativ nach Wahrscheinlichkeit sortiert, bis die Summe p erreicht (z. B. 0.9). Dynamischer als Top-k.
Penalties Strafen auf bereits generierte Token, um Wiederholungen zu reduzieren. Varianten: Repetition Penalty (auf wiederholte Token), Frequency Penalty (proportional zur Häufigkeit), Presence Penalty (binär: kam vor oder nicht).
