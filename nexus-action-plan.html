NEXUS AI-OS · Aktionsplan v1.0

Bottom-Up Implementation — Vom Code zum System

Ziel: NEXUS v0.1 in 4 Wochen lauffähig. Keine neuen Dashboards. Nur registrierte, funktionierende Bausteine.
Leitprinzip: "Kein Architektur-Chat. Nur Code und YAML."
NEXUS v0.1 ist kein Dashboard und kein Diagramm. Es ist ein Git-Repo mit registrierten Workflows, einer Knowledge Base und einer CLAUDE.md. Die Ordnerstruktur 00_REGISTRY / 10_LIBRARY / 20_RUNTIME aus deinem Google Drive ist die richtige Idee — aber sie muss mit Inhalt gefüllt werden, nicht mit weiteren Konzeptpapieren.

Regel: Kein neues Konzeptdokument, bevor nicht 10 Workflows registriert sind. Kein neues Dashboard, bevor nicht 50 Knowledge-Dateien existieren.

Anti-Pattern Guard — Warnzeichen erkennen
Wenn eines dieser Dinge passiert → STOPP
1. Du öffnest einen Chat mit "AI-OS Architektur" oder "Framework Design" im Titel → Schließen. Stattdessen eine .yaml-Datei schreiben.
2. Du erstellst ein Dashboard bevor 10 Workflows registriert sind → Dashboard löschen. Erst befüllen, dann visualisieren.
3. Du definierst neue Begriffe (Governance Engine, Conditional Pattern Discovery, Signal-Topologie) für existierende Konzepte → Bestehenden Begriff verwenden. Terminologie einfrieren.
4. Du startest ein neues Wissensprojekt in Claude/GPT statt in 10_LIBRARY/ → Direkt in die Knowledge Base schreiben.
5. Buchhaltung taucht als manueller Chat auf → Sofort buchhaltung.py aufrufen statt manuell sortieren.
